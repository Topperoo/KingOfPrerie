# Король Прерий

"Король Прерий" — это аркадный 2D-шутер, в котором игрок сражается с волнами наступающих монстров, собирает усиления и старается выжить как можно дольше, устанавливая новые рекорды. Игра вдохновлена мини-игрой "Journey of the Prairie King" из Stardew Valley.

## Организация Проекта

Данный репозиторий содержит все необходимые файлы для запуска и разработки игры "Король Прерий":
*   `index.html`: Основной HTML-файл для отображения игры.
*   `style.css`: Стили для игрового интерфейса и веб-страницы.
*   `game.js`: Основной JavaScript-файл, содержащий всю игровую логику (управление игроком, врагами, столкновения, отрисовка, бонусы и т.д.).
*   `images/`: Папка с изображениями и спрайтами, используемыми в игре.
*   `main.ts`: Сервер на Deno, который раздает статику и обслуживает API таблицы рекордов (`/api/scores`) через Deno KV. Для хостинга на GitHub Pages не используется.
*   `.nojekyll`: Пустой файл-флаг, отключающий обработку Jekyll на GitHub Pages.

## Запуск Локально

Для запуска игры на вашем локальном компьютере:

1.  **Клонируйте репозиторий:**
    Откройте терминал или командную строку и выполните команду:
    ```bash
    git clone https://github.com/... .git
    cd ...
    ```
    (Замените `ВАШ_ЛОГИН/ИМЯ_ВАШЕГО_РЕПОЗИТОРИЯ` на актуальный путь к вашему репозиторию).

2.  **Откройте `index.html` в браузере:**
    Просто найдите файл `index.html` в папке проекта и откройте его с помощью любого современного веб-браузера (например, Google Chrome, Mozilla Firefox, Microsoft Edge(Шутка, кому он нужен)).

    *Примечание:* Открытого в браузере `index.html` достаточно, чтобы играть. Рекорды при этом сохраняются в `localStorage` браузера, потому что серверный эндпоинт `/api/scores` недоступен. Чтобы проверить общую таблицу рекордов, запустите Deno-сервер командой `deno task start` и откройте http://localhost:8000.

## Развертывание (Deployment)

Игра развернута на [GitHub Pages](https://pages.github.com/) и доступна всем желающим по адресу:

**https://topperoo.github.io/KingOfPrerie/**

### Автоматическая публикация

Источником сайта выбрана ветка `main` (**Settings → Pages → Build and deployment → Source: Deploy from a branch**, папка `/ (root)`). После каждого `push` в `main` GitHub сам запускает workflow `pages-build-deployment` и обновляет сайт — его прогресс виден на вкладке **Actions**.

Отдельная сборка не нужна: игра состоит из статических файлов, поэтому Pages раздает репозиторий как есть. Файл `.nojekyll` отключает обработку Jekyll.

Чтобы обновить игру, достаточно закоммитить изменения и отправить их в `main` — новая версия окажется на сайте примерно через минуту.

### Настройка с нуля

Если хостинг нужно поднять в другом репозитории:

1. Положите в корень проекта пустой файл `.nojekyll`.
2. Откройте **Settings → Pages → Build and deployment**, выберите **Source: Deploy from a branch**, ветку `main` и папку `/ (root)`.
3. Сделайте `push` в `main` и дождитесь завершения `pages-build-deployment` на вкладке **Actions**.

### Таблица рекордов

GitHub Pages раздает только статические файлы, поэтому серверный эндпоинт `/api/scores` там недоступен. Клиент это учитывает: если API не отвечает, рекорды сохраняются и читаются из `localStorage` браузера. Таблица продолжает работать, но остается локальной для каждого игрока.

Чтобы рекорды снова стали общими, нужен работающий `/api/scores` на том же домене, что и игра. Для этого в репозитории лежит `main.ts` — сервер на Deno с хранилищем Deno KV, который раздает статику и обслуживает API:

```bash
deno task start
```

Достаточно развернуть этот сервер на любой платформе с поддержкой Deno (например, [Deno Deploy](https://deno.com/deploy)) — клиент сам начнет использовать API вместо `localStorage`, никаких правок в коде не потребуется.
